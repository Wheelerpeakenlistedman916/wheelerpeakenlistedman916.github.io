🤔 What Is GitCoffer?

If you write code, you probably use a tool called git. Git is a system that keeps a history of every change you make to your files. Many people also use it with websites like GitHub, where the project is stored on someone else's computer — usually called "the cloud."

GitCoffer does something different. Instead of sending your project to a company's servers, it stores a copy in an encrypted vault that lives on your own hardware. "Encrypted" simply means scrambled with a secret key so that nobody can read it without the passphrase you choose. If someone picks up your USB drive and plugs it into their own computer, they will see meaningless data, not your work.

You keep using the same git tools you already use — the command line, your code editor, or VSCode — and GitCoffer quietly handles the backup behind the scenes. From your point of view, you are still just "pushing" your project like always. The difference is where it lands: in a locked box on your desk instead of in the cloud.

🎯 Who Is This For?

  • People who value privacy. Your source code never leaves your possession.
  • People with unreliable internet. Backups work completely offline.
  • People who work in secure places. Some workplaces do not allow cloud services at all. GitCoffer works with no network connection whatsoever.
  • Students and hobbyists. A cheap USB stick becomes a proper versioned backup of every project you have ever written.
  • Small teams. Hand a drive to a colleague and they can hold an off-site copy of the project without any subscription.

📁 How It Works in Plain English

Think of a vault like a strongbox with a slot in the lid. Your git tools drop a copy of your project through the slot. The box scrambles everything it receives, wraps it up, and locks it. When you want a project back, the box checks your passphrase, unlocks, and hands you the files exactly as you left them.

Because the box lives on your own disk, there is no waiting for an upload, no monthly fee, and no company deciding whether your project is allowed to exist. You can unplug the drive, put it in a drawer, and plug it into a different computer later. The vault still opens with the same passphrase.

Working from VSCode

VSCode has a built-in source control panel. Once your vault is set up, you choose it as the remote — the destination — for your project. From then on, the little sync button in the corner of VSCode sends your changes into the vault. You do not need to memorise commands.

Working from the command line

If you prefer typing, the usual git commands work as normal, because GitCoffer behaves like any other git remote. There is nothing new to learn, only a new place for your code to go.

    🛡️ Keeping Your Vault Safe

    Your passphrase is the whole of the security. Choose something long and personal, and never store it in the same place as the drive. A written note kept in a drawer is safer than a text file sitting next to the vault, because anyone who finds the drive will also find the file.

    It helps to keep more than one copy. Because a vault is only a folder, you can duplicate it onto a second drive occasionally and store the two in different places. That way a lost or damaged USB stick never means a lost project.

    ❓ Common Questions

    Will this replace my normal git workflow?

    No. You keep using git exactly as you do now. GitCoffer only changes where your project is stored.

    Can I try it without risking a real project?

    Yes. Create a small test project, push it into a vault, and take your time exploring. A new project is safe to try.

    Does it need an internet connection?

    Only to visit the download page. Once GitCoffer is on your computer, the vault works entirely offline.

    What if I forget my passphrase?

    The vault cannot be opened. That is the price of real encryption, so treat the passphrase as carefully as you would a house key.

    Can I move my vault to a new drive?

    Yes. Copy the whole vault folder to the new location and point GitCoffer at it. The passphrase travels with the data, not the drive.
